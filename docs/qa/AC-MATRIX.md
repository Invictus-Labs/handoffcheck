# HandoffCheck AC matrix (owner: hc-qa)

Source of truth for the criteria: `docs/DOD.md` (PRD 5, 5b, 5c, verbatim). This file only maps each criterion to
real test ids, by behavior, and records the honest status. The PRD 5b "Proven by" placeholders (`<input binding>`,
`<sandbox boundary>`, ...) are reconciled below to the real test ids; the coordinator mirrors them into the PRD copy.

Status vocabulary. Automated column: `PASS` (automated tests green at the SHA in `docs/qa/QA-RECEIPT.md`, on the
synthetic `local-sandbox` provider with isolation none), `FAIL`, `NOT RUN`, `PARTIAL`, `PENDING_HUMAN_RECEIPT`. Live VM column:
`PASS` (a real VM receipt exists), `PARTIAL` (real VM receipt, with a named part not enforced), `BLOCKED` (named external blocker), `n/a` (the criterion does not execute workloads). Rule: any required cell that is NOT RUN, PARTIAL, BLOCKED or
PENDING_HUMAN_RECEIPT prevents the claim that the matrix passed (DOD 5b: "Any required NOT RUN, PARTIAL or BLOCKED row
prevents a claim that the matrix passed"). `node scripts/check-matrix.mjs` lints this file (real
test ids, no agent PASS for human receipts).

Test id format: `file :: test title`. Titles that begin with "negative control" seed a mandatory failure and assert the
verdict turns red. Some titles are generated per input (credential decoy kinds x locations, hostile manifests, hostile
archive entries, truncation offsets, decision-table rows); the family is named in Notes.

- Review-fix regression suites (one section per review finding, with positive controls): `tests/units/review-fix1.spec.ts`, `tests/units/review-fix1-cli.spec.ts`, `tests/units/gate.spec.ts` (the gate's own seeded-failure self-test).

  (security patterns, redaction, tar parsing, canonical JSON, state machine, manifest semantics, adapters, report
  renderers, CLI parsing and commands, engine edge cases, Lima protocol with a fake `limactl`).
